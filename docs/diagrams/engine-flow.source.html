결정적 증거가 부족하면 추가 확인
선택적 이익이면 개선 제안

파란 선은 기본 A 전략의 요청 흐름입니다.
모델의 판단과 코드의 검증은 서로 다른 역할입니다.

입력마다 확보하는 증거가 다릅니다

이미지: PNG/JPEG/WebP를 읽어 방향을 보정하고 PNG로 정규화합니다. 원본 해시와 증거 ID를 저장합니다.

URL: Playwright와 내부 MCP로 화면·DOM·접근성 정보를 수집하고 규칙 검사를 실행합니다.

이미지에는 DOM·클릭·스크롤 증거가 없습니다. 추가 확인은 질문으로 남으며 자동 실행되지 않습니다.

A / B / C는 기존 실행 전략입니다

A 기본: 한 번의 종합 평가 호출

B 선택: 분야별 독립 세션 3회 → 결과 통합

C 선택: 발견 → 같은 증거로 후보 재판정
유지·추가 확인으로 낮춤·기각만 수행합니다.

C는 새 증거 수집이나 사람의 검증이 아닙니다.
URL의 선택 기능 --verify와도 별개입니다.

검증기는 형식과 근거 연결을 확인합니다

필수 필드·증거 ID·주장 연결 등을 검사하고, 유효하지 않은 출력을 제외하거나 추가 확인으로 낮춥니다.

의미가 맞는지는 모델 판단에 의존합니다.
이미지에서 실제 결함인지 코드가 독립적으로 증명하는 구조는 아닙니다.

확정 문제 / 추가 확인 / 개선 제안을 분리해 저장하고 뷰어에서 보여줍니다. 제안은 이미지 리뷰에 적용됩니다.

이번 변경은 모델에 주는 이미지 판정 지침과 진단 버전입니다. 새 모델 학습이나 새 자율 에이전트를 추가하지 않았습니다.
기존 이미지 입력·증거 저장·출력 검증·보고서 구조 위에서 동작합니다. URL 판정 지침은 이번에 변경하지 않았습니다.
