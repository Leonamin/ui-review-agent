# 작업공간 실행 상태 전환 인수인계

지금 구현된 기능은 v1 상태의 읽기 전용 검증입니다. 다음 단계는 격리된 복제본에서 v2 후보를 사용해 기존 보고서 조회와 검토 재개를 검증하는 것입니다. 현재 뷰어와 워커는 v1 상태를 계속 사용합니다. 공개 소스의 설치와 실행은 [셀프호스팅 안내](self-hosting.md)를 따릅니다.

## 현재 상태

- 작업공간 API에서 검토를 접수·시작·재시도할 수 있습니다. 공개 응답은 `requestId`와 `attemptId`로 검토를 식별합니다.
- 공개본에는 작업공간·보고서 탐색과 결과 탭, 세로 스크롤 검토, 두 화면 스타일 비교, 폼 컨트롤 상단 정렬 검사가 포함돼 있습니다. [작업공간 화면](../viewer/features/workspaces/WorkspacePage.tsx), [세로 스크롤](../src/vertical-scroll.ts), [스타일 비교](cli.md), [폼 정렬 검사](../src/browser.ts)
- [변환기](../src/workspace-state-converter.ts)는 v1 스냅샷을 읽고 v2 후보를 메모리에서 만듭니다. 작업공간 요청, 시도, 보고서 소유권, 중복 제출 방지 기록을 변환하고 해석하지 못한 참조를 집계합니다.
- [보고서 검사](../src/workspace-state-audit.ts)는 복제본의 보고서 ID와 상대 경로, 소속과 숨김 상태, 보고서·캡처 해시를 대조합니다. [합성 테스트](../tests/workspace-state-converter.test.ts)는 이전·현재 회차가 섞인 데이터, 손상된 참조, 대기 시도의 ID, CLI의 재현성과 읽기 전용 동작을 검증합니다. [검사 테스트](../tests/workspace-state-audit.test.ts)는 보고서·캡처 확인과 복제본 경계를 검증합니다.

## 읽기 전용 검증 실행

합성 데이터가 담긴 격리된 `runs` 복제본으로 실행합니다. 복제본에는 `.review-service/state.json`과 참조된 보고서·캡처가 있어야 합니다.

```sh
pnpm run workspace:migration:dry-run --runs /path/to/isolated-copy
```

출력의 `hasPassed`는 변환·파일 검증 결과입니다. `cutoverBlockers`는 실행 중인 시도처럼 전환 전에 확인할 조건을 별도로 표시합니다. 후보 상태는 파일에 저장되지 않습니다. 저장된 절대 캡처 경로를 복제본 안으로 대응시켜야 하는 경우 `--original-runs-root`를 함께 지정할 수 있습니다.

## 격리 검증 결과 (2026-11-20)

- 합성 복제본 테스트 5개 통과. 보고서 ID·경로와 캡처 해시, 휴지통 숨김 상태, 대기·시작 대기 요청의 ID 보존을 확인했습니다. 읽기 전용 검사 전후에 합성 상태 파일과 보고서 파일이 유지됐습니다.
- **v2 보고서 조회와 대기 검토 재개 검증은 차단됨.** 별도 임시 폴더에 합성 v1 상태와 동일 입력에서 생성한 v2 후보를 각각 저장했습니다. v1 서비스는 시작됐고, v2 후보를 읽은 [ReviewService](../src/review-service.ts)는 `Unsupported review state` 오류로 시작 단계에서 중단됐습니다. v2 후보 파일의 내용은 유지됐습니다. 서비스가 v2를 읽을 수 있게 연결한 뒤 보고서 조회와 대기 검토의 실제 실행을 확인해야 합니다.

합성 복제본 테스트 재현 명령입니다.

```sh
pnpm exec tsx --test tests/workspace-state-converter.test.ts tests/workspace-state-audit.test.ts
```

## 다음 검증과 완료 기준

1. 격리 환경에서 v2 후보의 보고서 읽기 경로를 연결합니다. 이전 회차와 현재 요청이 섞인 작업, 단독 보고서, 다른 작업공간으로 이동한 보고서, 휴지통 보고서에서 기존 ID·상대 경로·표시 소속과 숨김 상태를 대조합니다.
2. 작업공간별 요청과 시도의 ID·상태·순서를 비교합니다. 대기, 재시작, 취소, 재시도를 확인하고 같은 입력을 다시 제출했을 때 기존 결과가 반환되는지 검증합니다. 로그인 대기 시도는 시작에 필요한 정보를 다시 입력하는 흐름도 확인합니다.
3. 상태·보고서·캡처·설정을 함께 복구하는 경로를 검증합니다. 전환 이후 생성된 기록을 보존하는 복구가 확인된 후 실제 저장 형식 전환을 계획할 수 있습니다.
